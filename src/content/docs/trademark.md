are **unregistered trademarks** claimed by Dmitry Andreev,
<da@issuerd.org> (the "Project"). This document will be updated with
application and registration numbers as they issue.

The Project claims trademark rights in the Issuerd Marks based on first
use in commerce, which commenced on September 21, 2026, with the
registration of the [issuerd.com](https://issuerd.com) domain.
The Marks may also be protected as unregistered trademarks in other
jurisdictions where the Project makes active use of them.

This policy explains how you may use the Issuerd Marks. It supplements
the Apache License 2.0, which governs the Issuerd source code: **open source
code is not the same as open trademark rights.**

## 1. What is covered

- The designation "Issuerd" in any case or styling (issuerd, Issuerd,
  ISSUERD)
- The Issuerd logo — brand assets in
  [`webclientsrc/public/brand/`](https://github.com/issuerd/issuerd/blob/main/webclientsrc/public/brand/):
  [`logo.svg`](https://github.com/issuerd/issuerd/blob/main/webclientsrc/public/brand/logo.svg) (light backgrounds),
  [`white-logo.svg`](https://github.com/issuerd/issuerd/blob/main/webclientsrc/public/brand/white-logo.svg) (dark
  backgrounds), and the small variants
  [`logo-small.svg`](https://github.com/issuerd/issuerd/blob/main/webclientsrc/public/brand/logo-small.svg) /
  [`logo-small-white.svg`](https://github.com/issuerd/issuerd/blob/main/webclientsrc/public/brand/logo-small-white.svg)
- Ecosystem package and project names: the `issuerd-*` crate family
  (`issuerd-core`, `issuerd-protocol`, `issuerd-token`,
  `issuerd-storage`, etc.) and derived tool names

## 2. Uses we explicitly allow — no permission needed

- **Nominative use.** Referring to the project accurately in speech,
  articles, documentation, comparisons ("Issuerd vs Keycloak"), package
  descriptions ("a plugin for Issuerd"), and conference talks.
- **Forks and modifications** of the source code under the Apache License
  2.0,
  provided you do not use the Issuerd Marks to name or brand the fork
  (see §3, §4).
- **Linking to** the official domains and repositories.
- **Contributing** to the project is implied acceptance of these terms.

## 3. Uses that require our written permission

- Using "Issuerd" as or within the name of a **fork, downstream product,
  hosted/managed service, or company** (e.g. "Issuerd Pro", "Issuerd
  Cloud", "Acme Issuerd").
- Registering **domains, social accounts, package namespaces, or app
  store listings** containing "Issuerd" other than the official ones
  operated by the Project: [issuerd.org](https://issuerd.org)
  (canonical), [issuerd.com](https://issuerd.com),
  [issuerd.dev](https://issuerd.dev),
  [github.com/issuerd/issuerd](https://github.com/issuerd/issuerd),
  and the Docker Hub account
  [`issuerd`](https://app.docker.com/accounts/issuerd).
- Publishing packages to crates.io, npm, Docker Hub, or similar
  registries under `issuerd` or `issuerd-*` names that are not released
  by the Project.
- Using the logo on merchandise or in marketing materials.
- **Implying endorsement**: stating or suggesting that your product,
  service, or fork is "official", "approved", or "certified" by the
  Issuerd project.

To request permission: trademark@issuerd.org.

## 4. Naming forks and derivatives

You may fork and redistribute the code under the Apache License 2.0, but your
fork must be named in a way that clearly distinguishes it from the
official project. Pattern: `[YourOrg] [descriptor] for Issuerd` —
e.g. "Acme hardened build for Issuerd" is acceptable; "Issuerd-Acme"
as a project name is not. "Compatible with Issuerd" is acceptable as a
description; "Issuerd-compatible" is not acceptable as a brand.

## 5. The logo

The Issuerd logo may be used in forks and documentation **only** in
unmodified form and solely to refer to the official project. Any other
use requires permission (§3).

## 6. Domains

Only the domains listed in §3 (and their subdomains) are official.
Community mirrors must not register domains containing "Issuerd"
without written permission.
